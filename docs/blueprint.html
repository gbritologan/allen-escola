00 · Leitura do briefing

A tese que governa todas as decisões abaixo

Um LMS organiza conteúdo. A Allen precisa organizar aplicação. Essa diferença não é de tom nem de UI — ela muda o modelo de dados, o que a Home mostra primeiro, o que conta como "concluído" e o que a plataforma consegue medir daqui a dois anos.

A unidade mínima da Allen não é a aula assistida. É a aplicação feita.

Por isso applications nasce como entidade de primeira classe no MVP — não como um checkbox dentro de lesson_progress. E por isso a plataforma começa a gravar sinais de habilidade desde o primeiro aluno, mesmo sem nenhuma IA no ar: quando o Skill Engine chegar, ele precisa de passado para ler. Passado não se cria retroativamente.

Contexto de negócio

Assinatura, 100% online, arena e não arquibancada. Não vira feature.

Experiência

Continuar · Aprender · Fazer · Evoluir. Governa hierarquia e navegação.

MVP

O ciclo completo: publicar → assistir → aplicar → progredir.

Futuro

Skills, agentes, evidências, B2B. Hoje só reservam espaço no schema.

Decisão: monorepo só quando o mobile existir

Começar com packages/ hoje é cerimônia sem retorno. A garantia de portabilidade vem de uma regra de lint: src/core/** não pode importar react, next/* nem nada de src/app/**. Quando o Expo entrar, src/core vira packages/core em um dia.

Decisão: o app nativo consome o Supabase direto

Nada de construir uma API REST intermediária "para o mobile". Com RLS correta, o cliente nativo usa o mesmo SDK, a mesma sessão e as mesmas políticas. A API própria só aparece se o vídeo ou a IA exigirem segredo de servidor — e aí é uma Route Handler pontual, não uma camada.

Decisão revista: sem sidebar na área do aluno 22 ago

A primeira versão deste documento propunha um rail fixo à esquerda. Ele foi descartado, e a objeção do Gabriel estava certa: um rail reserva 240px permanentes de chrome de aplicativo e espreme todo o conteúdo numa coluna estreita. É esse gesto — não os ícones — que faz um produto parecer painel de controle. A Allen é editorial.

No lugar dele: barra superior fina no desktop com conteúdo full-bleed, dock de vidro flutuante no mobile, e chrome que desaparece dentro da aula, voltando como overlay ao primeiro movimento do mouse. O vidro passa a ser vidro de verdade: há conteúdo correndo por trás dele.

O Admin mantém o rail. Ali é ferramenta, usada horas seguidas, e estrutura persistente ajuda — o que ainda reforça o §19: aluno e Admin devem parecer dois mundos.

Requisito que acompanha a decisão: rápido de aprender, zero risco de descoberta. Os quatro destinos ficam sempre visíveis, com rótulo em texto e não só ícone; o dock mobile também leva rótulo; nada existe apenas atrás de ⌘K; e o único movimento é a barra sumir ao rolar para baixo e voltar ao rolar para cima.

Sem parede de escolha na entrada. O primeiro acesso pergunta no máximo três coisas — o que você quer desenvolver, seu contexto de trabalho, quanto tempo por semana — todas puláveis, todas apenas ordenando a Home. Nunca trancando conteúdo.

05 · User flows

Os dois fluxos que precisam estar perfeitos

Core journey — o ciclo do aluno

Entra→ Home responde "onde eu parei"→ Continuar→ Aula retoma no segundo exato→ Para Saber→ Para Fazer→ Marca aplicação→ Próxima aula sugerida→ Jornada atualiza

O momento de maior atrito do produto inteiro

É a passagem vídeo terminou → e agora? Todo LMS empurra "próxima aula" e ensina o aluno a acumular. A Allen precisa parar ali: o fim do vídeo revela o Para Fazer em foco, com a próxima aula visivelmente em segundo plano. Um gesto de UI — e é a diferença entre uma escola de aplicação e uma videoteca.

Admin journey — do zero ao ar

Cria tema→ Novo curso (rascunho)→ Módulos→ Aulas→ Upload do vídeo em background→ Para Saber · Para Fazer→ Pré-visualiza como aluno→ Publicar
  • Rascunho é o estado natural. Tudo nasce invisível para o aluno. Publicar é um ato deliberado, com checagem do que falta (vídeo pronto? capa? Para Fazer?).
  • Upload nunca prende a tela. Envia direto do navegador para o provedor de vídeo, com progresso persistente — você continua escrevendo o Para Saber enquanto o vídeo processa.
  • Publicação em cascata é explícita. Publicar o curso pergunta se leva junto os módulos e aulas prontos. Nada some por acidente, nada vaza por acidente.

decisão enrollments derivada, não calculada

"Continue de onde parou" é a primeira coisa que carrega em toda sessão. Agregar lesson_progress a cada abertura fica lento com o catálogo crescendo. Um trigger atualiza enrollments na conclusão de cada aula, e a Home faz uma query indexada.

decisão format em vez de is_masterclass

Um enum aceita o terceiro formato que vai aparecer (série, workshop, intensivo) sem virar uma família de booleanos mutuamente exclusivos. Atende exatamente o que o briefing pede, com uma porta a mais.

decisão skill_signals desde o dia um

Uma tabela append-only, escrita por trigger, sem UI e sem custo perceptível. No dia em que o Skill Engine ligar, ele encontra meses de comportamento real em vez de uma base vazia. É o item de arquitetura mais barato e mais valioso deste documento.

preparado Evidências

applications.evidence é jsonb anulável com evidence_type. Arquivo, link, texto ou checklist entram depois sem migração destrutiva — e sem nenhuma complexidade agora.

08 · Permission model

A permissão mora no banco

O frontend esconde botões. O Postgres nega operações. Se a UI do Admin vazasse inteira para um aluno, ele não conseguiria ler nem escrever uma linha a mais.

Papel no JWT, não em JOIN

Se cada política RLS consultar profiles, é um JOIN por linha em toda leitura. O papel é espelhado no token via custom access token hook; a política lê auth.jwt() e custa O(1). Mudança de papel invalida a sessão.

Um único portão de acesso

Uma função tem_acesso(uid) concentra a regra de "esse usuário pode consumir conteúdo". Hoje devolve verdadeiro para qualquer conta ativa; quando a cobrança existir, muda em um lugar — não em quarenta políticas.

Os neutros intermediários são derivados do Navy, não de cinza puro: #B9C0DC para texto secundário e #7E87AB para terciário. Cinza neutro sobre azul-marinho parece sujeira; cinza enviesado parece decisão.

Tipografia

  • Inter Tight — títulos e números. Tracking negativo (−0.03em) nos tamanhos grandes.
  • Inter — corpo, interface, dados. tabular-nums em tudo que é número.
  • Fraunces Italic — no máximo um momento editorial por tela. Abertura de Masterclass, título de tema. Nunca em UI funcional.

Vidro, com regra escrita

Glass só onde há algo por baixo que importa: controles do player, modais, menu de comando, barra mobile, overlay de busca. Card de curso não é vidro. Página não é vidro.

Receita única: blur 22px, saturação 140%, borda superior mais clara que as laterais, sombra longa e difusa.

Motion — quatro primitivas nomeadas

NomeOndeDuraçãoCurva
riseentrada de conteúdo · 8px + fade, escalonado 40ms240ms(.2,.8,.2,1)
sheenloading · luz azul atravessando o skeleton1400ms looplinear
settleprogresso · barra alcança o valor sem elástico420ms(.32,.72,0,1)
bloomaplicação concluída · glow único que expande e some560ms(.16,1,.3,1)

Quatro primitivas, usadas em todo lugar. É isso que faz a plataforma parecer uma coisa só em vez de uma coleção de telas animadas. prefers-reduced-motion desliga deslocamento e loop, mantém opacidade.

Loading: nunca tela branca, nunca spinner

Cada rota tem skeleton com a forma real do conteúdo que vem — o layout não pula quando os dados chegam. O sheen azul percorre os blocos. Navegações internas fazem prefetch no hover, então na prática a maior parte já chega pronta.

               sem conhecimento de domínio · sem biblioteca de UI pronta

  • Sem biblioteca de componentes. shadcn/MUI/Chakra trazem uma identidade visual junto — e o pedido é o oposto disso. Primitivas próprias sobre Radix apenas onde acessibilidade é difícil (dialog, tabs, popover).
  • O peso do cliente é orçado. A rota da aula é a mais pesada e não passa de ~90KB de JS. O Content Studio pode ser pesado — só a equipe entra lá.
  • framer-motion só nas ilhas cliente. Entradas e hovers são CSS puro.

O analytics do Mux é ótimo, mas as métricas que decidem produto aqui são conclusão de aula e aplicação feita, e essas são nossas, não do player. confirmar preço vigente antes de contratar

14 · Divergências

Onde eu não segui o briefing ao pé da letra

format no lugar de is_masterclassO briefing pede o booleano. Um enum entrega o mesmo comportamento e absorve o próximo formato sem refatorar catálogo, filtros e busca.
Masterclass não vira item de navegaçãoEla ganha superfície própria e apresentação premium, como pedido — mas como conteúdo em destaque, não como quinta aba. O briefing pede julgamento de UX; esse é o julgamento.
enrollments como tabela derivadaUma tabela a mais que o briefing não lista. Justificativa: é o que segura a promessa de "continue de onde parou" instantâneo quando o catálogo crescer.
skill_signals escrevendo no MVPO briefing pede para não implementar a camada de IA agora — e não estou implementando. Estou apenas gravando o histórico que ela vai precisar ler, a custo praticamente zero e sem nenhuma interface.
subscriptions sem cobrançaBilling fica fora. A tabela e o portão de acesso entram para que ligar a cobrança depois seja uma mudança em um ponto, e não uma auditoria de todas as políticas.
Registries de componentes entram — as convenções do shadcn, não o tema 22 agoA versão 0.1 deste documento vetava bibliotecas de componentes. O veto era largo demais: 21st.dev, Cult UI e Skiper UI publicam código de copiar-e-colar, que passa a ser nosso. Adotamos as convenções deles (cn(), cva, Radix, motion) e uma ponte de tokens que apelida --background, --primary, --border e companhia para os tokens Allen — um componente colado nasce navy e azul Allen sem editar cor. O que continua vetado é herdar identidade: nada entra com cor, raio, sombra, fonte ou timing próprios.

Existe base de alunos hoje?Se houver gente em outra plataforma, importação e migração de progresso entram no escopo e mudam a Fase 5.
Acesso no lançamento: aberto a quem tem conta, ou por liberação manual?Define o comportamento inicial do portão de acesso. Liberação manual é trivial agora; cobrança automática é outro ciclo.
Quem produz conteúdo além de você?Se houver mais de um conteudista, o Content Studio precisa de estados de revisão. Se for só você, publicação direta é melhor — menos cerimônia.
Quantos cursos existirão no dia do lançamento?Três cursos e trinta cursos pedem Home, Explorar e busca diferentes. Prefiro projetar para o número real do dia um, com folga para crescer.
Data de lançamento?Não muda a arquitetura — muda o que eu corto primeiro se a Fase 8 apertar.

Próximo passo, se você validar: Fases 2, 3 e 4 juntas — design system em código, repositório com a fronteira de domínio configurada e as migrations do banco com seed. É o alicerce sobre o qual todo o resto para de ser opinião e vira produto.
